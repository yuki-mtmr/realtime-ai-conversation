# パターン 4: 3D / WebGL

下のコードブロックをそのまま新しい Claude セッション（Opus 5.5）に貼る。

```
# 目的
自社の技術力を示すショーケースの LP を 1 ページ作る。
主役は、このリポジトリに用意済みの 4 つのアプリ。LP はこの 4 つを紹介するためのもの。
見る人: 旅行業の役員（技術者ではない。数秒で「すごい」と「任せられる」を感じてほしい）。
見終わった時の感想: 「この会社なら、うちの旅行体験を次の水準に上げられる」

# 最初にやること（実装前に、ここで止まって私の確認を待つ）
リポジトリ内から、紹介する 4 つのアプリと、それぞれに用意された文言（説明・開発背景など）を探して読む。
アプリごとに次を一覧にして提示する:
- アプリ名 / 場所（ディレクトリ・ファイル）
- 用意された文言（原文のまま）
- スクショ・画像・デモ動画の有無と場所
- 文言とコードから読み取れる技術的な見どころ（LP で何を強調するか）
4 つ見つからない、または文言が見当たらない場合は、推測で埋めずにその旨を報告する。

# 文言の扱い
- 用意された文言は仮。今後それぞれの開発者が差し替える
- 文言は勝手に書き換えない・要約しない。原文をそのまま使う
- 見出し用の短い一文が必要な場合は、原文から抜き出す。新しく作る場合は「案」として別の項目に入れ、私に確認する
- 文言と画像はコンポーネントに直書きしない。1 つのデータファイル（例: src/content/apps.ts）にまとめ、差し替えはそのファイルだけで済むようにする
- 文言の長さが今の 0.5〜2 倍になっても崩れないレイアウトにする
- 文言が無い項目は「［開発者記入予定］」と表示する。数字や実績は作らない
- 画像が無いアプリには、差し替え用の枠（アプリ名入り）を置く

# デザインの方向性（このパターン固有）
3D / WebGL 主体の没入型 LP。主役は没入感。
- スクロールに合わせてカメラが 3D 空間を進み、4 つの「駅」に順に立ち寄る。駅 1 つ＝アプリ 1 つ
- 各駅で、そのアプリの名前・説明・開発背景と画像を 3D の前に重ねて表示する
- 抽象的・ハイテクな質感（光、パーティクル、ガラス、フォグ）。写実ではなく「未来的」
参照: https://www.igloo.inc/ （スクロールで 3D 世界を進む構成）/ https://lusion.co/ （WebGL の質感）
真似るのは カメラワークと質感 だけ

# 制約
- 4 つのアプリの中身と文言は必ず読む（LP の中身の元になるため）
- ただし、リポジトリ内の既存の LP 試作やスタイル（CSS・デザイントークン・レイアウト）は、見た目の参考にしない
- 流用してよいのは ビルド設定・ディレクトリ構成 のみ
- 技術: Next.js + TypeScript + React Three Fiber + drei + postprocessing + GSAP ScrollTrigger
- モバイルでは描画負荷を下げる（DPR 上限 1.5、パーティクル数を削減）
- WebGL 非対応時は静止画にフォールバック。アプリの文言は 3D が無くても読めるようにする

# 進め方（各段階で止まって私の確認を待つ）
0. 上の「最初にやること」の一覧を提示
1. コンセプトを 3 行で書き、デザイントークン（書体 2 種・配色 5 色・余白スケール）を定義
2. セクション構成をワイヤー（テキスト）で提示。4 つのアプリがどこに、どの順で出るかを明記
3. 実装。セクションを 1 つ作るたびにスクショを撮り、参照と比べて自己修正
4. 最後に 375px / 1440px で確認。prefers-reduced-motion 時は演出を控えめにする

# 完成条件
- 最初の 1 画面で方向性が伝わる
- 4 つのアプリそれぞれに、名前・説明・開発背景・画像（または差し替え枠）が載っている
- 文言はデータファイル 1 つの差し替えで全部更新できる
- 1 セクション 1 演出まで。演出同士を競合させない
- 60fps を目安に、重い処理は画面外で止める
```
